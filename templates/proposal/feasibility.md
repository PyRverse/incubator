# Feasibility

## Alternatives audit

Record search date and terms. For each relevant project link primary documentation and distinguish identical method, partial implementation, alternative statistics, and R wrapper. Record version, runtime requirements, covered functions, maintenance evidence, license, and outstanding checks. Do not infer completeness from a project name.

## Work and risks

Describe statistical dependencies, numerical routines, input semantics, computational cost, API choices, and expertise needed. Separate observed upstream behavior from implementation hypotheses. List likely differences in optimization, floating-point arithmetic, RNGs, missingness, and factor coding.

## Scope and effort

Define research, fixture generation, prototype, and review work. Label estimates as provisional and identify dependencies before offering dates. Describe success criteria for proceeding, collaborating, or stopping.

## Licensing

Link evidence and record the proposed implementation approach. An upstream license is not automatically the correct license for newly written code, and translation is not automatically independent. Include dependencies and data.
